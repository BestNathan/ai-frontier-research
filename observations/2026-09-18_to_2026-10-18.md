## 1. Core takeaway

The interesting trend is **bottleneck migration**. Better coding agents are producing software and investigations fast enough that source control, CI, evidence verification, security containment, integration and human attention become prominent limiting resources.

However, the two companies published different kinds of evidence in this window:

- **Anthropic** provided a deep internal source-control redesign account (Scion) and security/evaluation research on automated vulnerability finding and unintended autonomous actions.
- **OpenAI** provided a concrete repository-maintenance/CI optimization case study, operational architecture guidance for model failover, and platform feature announcements for managed agent environments, automated review and security.

That is a comparison of **publications**, not proof that one company prioritizes or solves a particular problem better internally.

## 4. Synthesis: engineering directions suggested by the evidence (Inferred)

### A. The source-code substrate becomes a shared service

Scion demonstrates one approach to huge object and history access pressure. Managed cloud workspaces demonstrate a different integration surface. The general concept is **separate immutable code objects, mutable workspace views, and branch integration coordination**.

Research gate: compare full clone vs Git bare mirror/worktree vs lazy object fetch at fixed repository SHA and N-agent load. Record correctness along with warm/cold P95 and I/O cost.

### B. An agent's downstream value depends on independent evidence

A model can find bugs, optimize quantum circuits, or propose deleting code, but a production decision requires reproducers, tests, formal checks, usage telemetry, provenance, or approvals. More proposals simply move the bottleneck onto validation.

Research gate: estimate useful **verified** findings / reviewer minute and false-negative/false-positive rates, not raw detections.

### C. Durable work and retry safety are separate concerns

OpenAI explicitly warns that rerouting an inference call does not resume an in-flight stateful agent with external actions. Anthropic's unintended-action report shows why autonomous recovery without clear boundaries is dangerous.

Research gate: inject a timeout after a tool has performed an irreversible external operation but before the agent has a confirmed result. Measure duplicate effects and recovery policy compliance.

### D. Maintenance should be part of an autonomous engineering loop

A growing repository accumulates stale flags, code paths, test overhead and operational entropy. OpenAI's maintenance work demonstrates how access to historical context plus production telemetry can identify actionable cleanup. Scaling it safely requires staged small PRs, differential tests and recorded before/after metrics.

Research gate: measure realized cost savings and defect escapes from a maintenance agent under bounded human review.

### E. Human attention requires its own reliability budget

Anthropic reports agent activity exceeding employee time; OSS Scanner reports more findings than experts can process. OpenAI's maintenance case study likewise relies on humans reviewing evidence and optimizing candidate selection.

Research gate: track exceptions per reviewer hour, time-to-actionable-summary, escaped defects and reviewer workload alongside GPU/tokens/CI costs.

## 5. Recommended first experiments

1. **Workspace-scale benchmark:** 10/100/1000 isolated agents; cold/hot cache and exact SHA; disk, checkout latency, stale-view and merge errors.
2. **Verified security-finding pipeline:** fixed code revision; agent candidate → runnable reproducer → deduplication → severity → reviewer; precision, recall and attention minutes.
3. **Incremental CI integrity:** choose impacted tests, replay known regressions, check false negatives and evidence fingerprint validity.
4. **Durable action policy:** provider timeout, lost tool response and sandbox restart with a fake external service; guarantee no uncontrolled duplicate writes.
5. **Maintenance ROI:** telemetry-grounded feature flag and dead-code proposals, human reviews, preserved safety paths and observed CI/CPU change.
