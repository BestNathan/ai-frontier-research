## Research synthesis: which bottlenecks are being addressed?

### Priority A — Agent-scale engineering throughput

**Verified disclosure:** Scion reflects an internal move from per-client Git operations to service-side versioning, content-addressed objects, layered caches and separate immutable changeset creation from shared ref updates. Anthropic also reports work on code review, search and IAM.

**Inferred focus:** growing agent throughput shifts constraints to repository materialization, merge coordination and CI cost. Do not infer Scion powers the public Claude Code GitHub integration.

**Open questions:** search index consistency across old workspace revisions; semantic merge conflict rates; relative economics versus a simpler Git mirror/worktree design.

Domain: [Source control](../../domains/source-control.md), [Verification](../../domains/verification.md).

### Priority B — Autonomous security auditing and bounded agent action

**Verified disclosure:** OSS Scanner pushes candidate findings and proposed fixes to maintainers at scale, but acknowledges limited human review. Separately, the Oct 9 report shows unintended actions even in controlled tasks and describes defense-in-depth and transcript monitoring.

**Inferred focus:** ability to produce security work faster exposes **validation throughput** and **containment** as paired bottlenecks. High finding volume without deduplication, confidence, reproducers and policy controls can move cost to downstream maintainers.

Domain: [Security](../../domains/security.md), [Verification](../../domains/verification.md).

### Priority C — Human oversight and long-horizon autonomy

**Verified disclosure:** the employment study describes rapidly increasing agent hours and changing work patterns. Project Swap explores delegation and multi-agent governance. The quantum article illustrates a goal/evaluator loop beyond ordinary coding.

**Inferred focus:** humans shift from executing individual steps to defining goals, policies, evidence standards and exceptions. These studies do **not** demonstrate that the entire software release pipeline is autonomously safe.

Domain: [Orchestration](../../domains/orchestration.md), [Evaluation](../../domains/evaluation.md).

## Working direction summary (interpretation, not an announced company roadmap)

1. **Scale the engineering substrate** for continuous agent-made changes: source control, caching, review, search and CI.
2. **Scale verification throughput** for agent-generated security findings and software changes, with evidence that can be independently checked.
3. **Contain autonomous tool use** with bounded execution, monitoring, least privilege, and tested recovery.
4. **Manage human attention as a scarce resource**, using clear task intentions and higher-quality exception escalation.
5. **Extend closed-loop autonomy into technical research** where independent evaluators constrain outcomes.

These are researcher's **inferences from selected public publications**. They are not internal plans confirmed by Anthropic.

## Experiments worth doing

- Compare Git shared-mirror/worktree against lazy content access with fixed workloads and hot/cold caches.
- Assess scanner-report reproducibility, false-positive rate, deduplication and reviewer time.
- Inject unsafe tool attempts and delayed responses to evaluate containment and side-effect recovery.
- Test whether automated evaluators reduce post-integration failures, not just generate more patches.
